# Agent Instructions

1. `CHANGELOG.md` is automatically generated by `git-cliff`; do not edit it manually.
2. Python bindings under `example/showcase/python/showcase_bindings/`,
   `example/counter/python/counter_bindings/`, and `tests/build-artifacts/` are generated.
   Rust server bindings are generated in Cargo's `OUT_DIR`. Update the state
   definition (`example/counter/gui/src/lib.rs`,
   `example/showcase/gui-core/src/state/`, or `tests/shared-test-states`) or generator and
   rebuild; do not edit generated files. Run `cargo build -p counter_gui` or
   `cargo build -p showcase_gui` to generate the respective Python bindings.
   Run `cargo run -p egui_states_test_support --bin prepare-test-bindings` for
   independent tests.
3. `README.md` is the primary user guide, `docs/architecture.md` explains the
   synchronization model, and public API behavior belongs in rustdoc or Python
   docstrings next to the implementation.
4. Python docstrings follow the Google-style format parsed by Sphinx Napoleon.
   Use `name (Type): description` for required parameters and
   `name (Type, optional): description` when the signature supplies a default.
   A required parameter whose type permits `None` is not marked optional. Start
   `Returns:` descriptions with the return type. Keep docstring types consistent
   with the signature; summary lines must end with punctuation and stay within
   80 characters.
